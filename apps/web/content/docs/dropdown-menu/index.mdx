## Installation

<ComponentOnly>

Install the styled component from our registry:

```npm
npx shadcn@latest add {{REGISTRY_URL}}/r/dropdown-menu
```

Just like shadcn/ui wraps Radix/Base UI primitives, our styled component wraps the `@bazza-ui/react` primitive with base styles and useful helpers, fitting in perfectly with your existing shadcn/ui components.

The styled component is added to your components directory as `dropdown-menu-preview.tsx` to prevent conflicts with your existing dropdown menu component file.

```tsx
import { DropdownMenu } from '@/components/ui/dropdown-menu-preview';
```

You can rename the file once you're done migrating.

</ComponentOnly>

<PrimitiveOnly>

Install the unstyled primitive from npm:

```npm
npm install @bazza-ui/react{{RELEASE_CHANNEL}}
```

```tsx
import { DropdownMenu } from '@bazza-ui/react';
```

</PrimitiveOnly>

## Anatomy

```tsx
<DropdownMenu.Root>
  <DropdownMenu.Trigger />
  <DropdownMenu.Portal>
    <DropdownMenu.Backdrop />
    <DropdownMenu.Positioner>
      <DropdownMenu.Popup>
        <DropdownMenu.Arrow />
        <DropdownMenu.Surface>
          <DropdownMenu.Input />
          {/* Tabbable header/footer content */}
          <DropdownMenu.Header />
          <DropdownMenu.List>
            {/* Scroll up/down arrows */}
            <DropdownMenu.ScrollUpArrow />
            <DropdownMenu.ScrollDownArrow />
            {/* Items */}
            <DropdownMenu.Item>
              <DropdownMenu.Icon />
              <DropdownMenu.Shortcut />
            </DropdownMenu.Item>
            {/* Groups */}
            <DropdownMenu.Group>
              <DropdownMenu.GroupLabel />
            </DropdownMenu.Group>
            {/* Checkbox items */}
            <DropdownMenu.CheckboxItem>
              <DropdownMenu.CheckboxItemIndicator />
            </DropdownMenu.CheckboxItem>
            {/* Radio group + radio items */}
            <DropdownMenu.RadioGroup>
              <DropdownMenu.RadioItem>
                <DropdownMenu.RadioItemIndicator />
              </DropdownMenu.RadioItem>
            </DropdownMenu.RadioGroup>
            {/* Separator */}
            <DropdownMenu.Separator />
            {/* Submenus */}
            <DropdownMenu.Submenu>
              {/* Submenu Trigger */}
              <DropdownMenu.SubmenuTrigger>
                <DropdownMenu.SubmenuTriggerIndicator />
              </DropdownMenu.SubmenuTrigger>
            </DropdownMenu.Submenu>
            <DropdownMenu.Empty />
          </DropdownMenu.List>
          <DropdownMenu.Footer />
          {/* Arbitrary tabbable content */}
          <DropdownMenu.FocusZone />
        </DropdownMenu.Surface>
      </DropdownMenu.Popup>
    </DropdownMenu.Positioner>
  </DropdownMenu.Portal>
</DropdownMenu.Root>
```


  </Example.PreviewCode>

### Close on click

Use the `closeOnClick` prop to control whether the menu closes when an item is selected.

`<DropdownMenu.Item>` closes the menu by default, while `<DropdownMenu.CheckboxItem>` and `<DropdownMenu.RadioItem>` keep the menu open by default.

### Search

Search works out-of-the-box and fully customizable; use the `<DropdownMenu.Input>` part.

The `value` and `keywords` props are used to filter the items.

<ComponentOnly>
  <Example name="dropdown-menu-search">
    <Example.PreviewCode>
      ```tsx
      <DropdownMenu.Item value="bug" keywords={['issue', 'fix']} />
      ```
    </Example.PreviewCode>
  </Example>
</ComponentOnly>

We recommend **always** rendering the `<DropdownMenu.Input>` part.

If you want a cleaner look, the `hideUntilActive` prop can be used to hide the input until the user starts typing. The rest of the examples on this page demonstrate this.

<ComponentOnly>
  <Example name="dropdown-menu-hidden-input">
    <Example.PreviewCode>
      ```tsx
      <DropdownMenu.Input hideUntilActive />
      ```
    </Example.PreviewCode>
  </Example>
</ComponentOnly>

### Radio group

Use the `<DropdownMenu.RadioGroup>` and `<DropdownMenu.RadioItem>` parts to create menu items that work like radio buttons.

Optionally, add a label using the `<DropdownMenu.GroupLabel>` part.

```tsx
<DropdownMenu.RadioGroup
  value={sortBy}
  onValueChange={(value) => setSortBy(value)}
```

### Submenu

Create nested menus by starting with the `<DropdownMenu.Submenu>` part.

Use the `<DropdownMenu.SubmenuTrigger>` part to create a menu item that opens the submenu when highlighted.

Then, compose with the same parts for the root menu to render the popup.

<ComponentOnly>

<Example name="dropdown-menu-submenu">
  <Example.PreviewCode>

  ```tsx
  <DropdownMenu.Submenu>
    <DropdownMenu.SubmenuTrigger>
      More details
    </DropdownMenu.SubmenuTrigger>
  </DropdownMenu.Submenu>
  ```

  </Example.PreviewCode>
</Example>

</ComponentOnly>

### Subpage

Use subpages as a natural replacement to modals, great for workflows such as item creation.

Use the `<DropdownMenu.Subpage>` part, give it a `pageId`, and wrap it around a new `<DropdownMenu.Surface>` with the subpage content.

Render a `<DropdownMenu.SubpageTrigger>` and wire it up using the `targetPageId` prop.



<ComponentOnly>

<Example name="dropdown-menu-subpage" />

</ComponentOnly>

For data-first subpages, `pageId` is the subpage's Resolved ID (`node.id`); pass it straight to `<…Subpage pageId>`. Imperative subpages choose their own `pageId` string.

In virtualized lists, groups and radio groups flatten into independent rows: `label`/`renderLabel` become standalone label rows, and each item mounts on its own. Container `render` functions on group and radio-group defs are ignored in virtualized mode (a dev-only warning is logged) — item-level `render` and separator `render` are always honored.

### Tabbable content

By default, pressing Tab or Shift+Tab inside an open menu closes the whole menu tree.

To put interactive controls inside the popup, wrap them in the `<DropdownMenu.Header>`, `<DropdownMenu.Footer>`, or `<DropdownMenu.FocusZone>` parts. Their tabbable children join the menu's Tab cycle: Tab moves from the input (or the list, when there is no input) through the controls in DOM order and wraps around, instead of closing the menu. Shift+Tab cycles in reverse.

Arrow keys never leave the list: they drive the highlight from the input or the list, and while a header or footer control has focus they are inert — the list highlight stays where it was.

<ComponentOnly>

<Example name="dropdown-menu-footer-actions">
  <Example.PreviewCode>

  ```tsx
  <DropdownMenu.Footer>
    <Button variant="ghost" size="sm">Clear</Button>
    <Button size="sm">Apply</Button>
  </DropdownMenu.Footer>
  ```

  </Example.PreviewCode>
</Example>

<Example name="dropdown-menu-header-toolbar" />

</ComponentOnly>

In nested menus, pressing Tab inside a submenu that has no tabbable content closes the submenu chain and moves focus to the nearest ancestor surface that has some. `Header` and `Footer` are thin conveniences over `FocusZone` — reach for `FocusZone` directly for arbitrary tabbable regions.
